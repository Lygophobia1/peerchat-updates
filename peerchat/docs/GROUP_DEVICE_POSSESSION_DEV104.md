# Existing signing-identity possession evidence — dev.104

This prerequisite packages the existing domain-separated `PeerChat/group-device-identity/v1` original-message signature with its canonical account, exact Peer ID and existing public signing identity. Native and server parsers bound the full record, validate exact purpose/fields/public-key hash and use existing P-256/SHA-256 raw-signature verification. No private key, new key, credential, TLS identity or mailbox identity is introduced. Signing goes through the existing opaque provider when present.

An internal server database boundary accepts publication only for the authenticated account/device matching an already-registered device. A same-account registered requesting device can retrieve verified target evidence. Publication is idempotent, preserves existing evidence and changes no group roster/generation. Storage is public signed evidence with account/device foreign-key cleanup, not secret material. Readback independently verifies the signature and stored mapping; malformed or mismatched evidence fails closed rather than silently overwriting it. Account-device removal removes eligibility. Group-specific revocation remains governed separately by current signed group approval and roster generations.

These methods are not exposed as RPCs or UI actions yet. They neither enroll the target nor authorize key handoff, messaging or old history. Eventual RPC integration must enforce the exact authenticated server device session, not merely caller-supplied references. The target's possession proof is not a bearer credential; the approver's separate signed group/epoch-bound proof and current authoritative membership remain required.
