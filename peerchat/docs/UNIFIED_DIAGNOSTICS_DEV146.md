## Implementation and lifecycle

History diagnostics never call native Archive, StartSync, RefreshCurrent, authorization or scheduler commands. They consume the existing owner/generation-checked cache. Opening Settings is not required for automatic sync or collection. The cache's existing worker cadence is unchanged; an unavailable/stale-owner cache produces unavailable output rather than borrowing the previous account's result.

Logs read only the existing profile log and retained getter. They do not create a log/retention service, recover markers again, add failures, update markers, or write live samples. The global `%TEMP%/PeerChat-ui-timing.log` is not safely profile-attributed and is therefore inventoried but not read/exported. The existing retained store may return an empty list for missing, corrupt or unavailable data; the UI does not call that proof of error-free operation.

Both views use the existing application timer, approximately once/sec while their section is visible, with in-place value/list updates and close-time unsubscription. No extra timer/thread or continuous database writes. Historical selections use actual recorded failure IDs; a removed selection cannot silently pick an unrelated failure. The original diagnostic footer can open unified Connections, or the exact retained failure under Logs/Failures. The old window and notification behavior are not removed.

Existing file/DM/Group graph bounds, pause and exports remain intact. History/Logs graph pausing is disabled with a clear unavailable explanation, since no real graph metric is connected there. Normal operation has no sample pages. Developer-only previews for previously approved sections and private isolated test providers remain separate; screenshots are marked SAMPLE FIXTURE — NOT PHYSICAL ACCEPTANCE.

Metadata exports preserve identifiers and UTC within existing bounds. Oversized Logs exports include an explicit bounded-export notice and invite subsystem/individual-record selection. Retained log parsing uses the newest bounded text rather than truncating older-first before parsing. Content-labeled fields, credentials, tokens, PEM private keys and authorization values are redacted.

## Physical acceptance checklist

1. Connections: connected/disconnected/reconnecting state, session selection, retained event/failure filtering, original window and Unified Diagnostics entry; opening diagnostics must not reconnect messaging.
2. File Transfers: use a bubble's Open Diagnostics during a real send/receive and after completion. Verify selected file/recipient, confirmed bytes, Mbps, retained average/duration, pause and truthful unavailable fields. No 5 GB test; limit remains 256 MiB.
3. DM Calls: voice, screen-only and combined; correct peer/session, local audio and sharer/viewer data, separate control/media routes. End/restart/reconnect must not reuse stale generations.
4. Group Calls: multiple voice participants and one sharer/two viewers simultaneously; join/leave/reconnect/room switches; correct local decoder ownership. Delayed second-viewer cause remains unproven, not fixed here.
5. History Sync: inspect active synchronization and a previous completed result together; successful/partial/failed/idle outcomes, source versus reader counters, authorization evidence, completion refresh and auto-sync state. Opening/closing diagnostics must not start sync or change permissions.
6. Logs/Crash Reports: search, severity/subsystem filters, select/expand failures, local/UTC details, copy and scoped export. Empty crash data must say Not retained/Not instrumented; unfinished operations must not be presented as confirmed crashes.
7. Resize/scroll all contexts, test display scaling, pause/resume available graphs, copy/export, open/close during active work and switch profiles. Confirm no metrics migrate to another profile/call/transfer/participant.
