# Complete Windows diagnostics export

The former Save Diagnostics action used the same formatter and privacy filter as clipboard output. Both clipped reports at 65,536 characters, and snapshot capture clipped individual sections before formatting. Saving that representation could omit late History Sync, transfer, eligibility or event details even though the available subsystem snapshot contained them.

Connection & Diagnostics now has **Export Diagnostics…**. The diagnostics/graphs window also has this action, separate from its existing selected-view preview export. The new action always opens the normal Windows Save File dialog and exports the complete available current subsystem snapshot plus existing bounded retained failures, regardless of the selected tab or conversation. Copy Summary/Copy Diagnostics remain available with their existing bounded presentation behavior. No clipboard or PeerChat file transfer is used to save the report; no upload occurs.

The report includes build, capture/export UTC, snapshot/failure/operation identifiers, all available source sections, complete frozen group metadata, existing connection/event/retry records and native transfer/eligibility/History Sync fields. A metadata-only correlation section adds currently loaded message IDs, sender devices, delivery states, conversation/group IDs, public device identities, session/account generations, and existing transfer-catalog sender/recipient/transfer identities and failure state. It excludes message text, attachment filenames and private paths. No historical message scan or new telemetry collector is introduced. If a subsystem never recorded a precise native failure or duration, the report does not invent one.

Capture reads existing dispatcher-owned/native snapshot sources once, sequentially, and freezes the resulting strings and copied metadata. It is not an atomic transaction across independent transports. Formatting, redaction and disk I/O then run on a worker, without holding a messaging-engine gate while writing the report. Existing source snapshot calls can still require their normal brief native synchronization. Already bounded source logs and retained failure snapshots remain bounded; an export cannot recover records that were never retained.

The file writer processes lines through UTF-8 without a whole-report formatter/string copy. It reuses the existing sensitive-field redaction without its clipboard-length cap and additionally filters plaintext-labeled fields, private key blocks/material, credential-bearing URLs and private absolute file paths. Public correlation identifiers remain visible. Bounds are explicit: at most 1,048,576 characters per source line and 33,554,432 output characters per report. Exceeding a bound or encountering an unterminated private-key block fails the operation; it never silently clips a successful file.

Output is written to a unique sibling temporary file, flushed, then atomically moved/replaced at the user-selected destination. Cancellation or write/redaction/validation failure leaves an existing destination intact and removes the partial temporary file where the filesystem permits. Picker cancellation starts no capture/write. A filesystem that cannot perform the atomic replacement reports an error instead of falling back to a destructive overwrite. The export adds CPU/disk work proportional to the available report and temporarily holds frozen source strings, but does not change connection scheduling, transfer caps/windows, security state or user data.

## Validation

- `tests/test-diagnostics-file-export.ps1`: passed a 3,309,459-byte report fixture, with late fields beyond clipboard limits, UTF-8/Unicode, message/transfer/failure correlation, immutable capture, redaction including late credentials/plaintext/paths/private keys, cancellation, failed writes, preserved existing destinations and no leftover partial report.
- `tests/test-diagnostics-file-export-ui.ps1`: compiled all production managed Windows sources and passed the real UI capture path without a native profile, clipboard or interactive picker. Verified metadata from both selected and unselected conversations, transfer sender/recipient IDs, a source exceeding 65k, and exclusion of actual message text, filenames and disk paths.
- `tests/test-windows-mailbox-reliability.ps1`: all production managed source compiled and existing outgoing/incoming/receipt fairness plus authenticated eligibility validation regressions passed.

The normal Save File dialog and exported report should still be exercised during physical Windows acceptance. Host fixtures do not establish Motorola connection/transfer reliability or acceptance. No phone/server access, deployment, version change or release packaging was performed for this checkpoint.
