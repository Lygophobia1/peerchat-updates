## Confirmed repair

Android saved-session resume previously held `MessagingBackend.gate` across the
signed challenge/resume network exchange. `send()` needs that same gate to commit
its local encrypted queue entry. A network wait could therefore delay the local
durable Send result even when protected local history and identity were available.

Saved resume now runs network work outside that gate. One current request is
shared by concurrent restore callers and background retries. Each request is
fenced by its exact request identity, authorization generation and foreground
lifetime. Native signing and publication reacquire the gate and verify the same
profile. A separate credential gate serializes the exchange against explicit
password enrollment, saved-credential replacement and sign-out revocation; lock
order is credential gate before application gate. A late result never logs out
its old bound session, since doing so could revoke newer remembered authority.
Existing protected credentials and transient-failure retry classification remain.
Authentication/TLS errors reach callers without a future-wrapper exception.

The remaining synchronous resume helper is restricted to explicit login with
lock-order assertions. Password login, enrollment and credential replacement
still hold the application gate. This repair does not claim to make first-ever
password enrollment nonblocking. It changes neither recipient authorization nor
encrypted payload, historical-access, mailbox ACK or group voice semantics.

## Read-only Pi observations and architecture assessment

The existing live process was reverified as PID 18001 running dev.186 with its
dev.186 configuration. A quiet sample reported load averages 0.00 / 0.02 / 0.00.
No deployment or configuration change followed.

The available rotated logs covered 2026-10-19 06:04:29 through 2026-10-20
20:17:22 UTC in the selected post-deployment window. Of 17,360 lines, bounded
timing extraction found five `cache_dm_append` slow samples (maximum 505.532 ms)
and two `cache_other` samples (maximum 2,191.944 ms). No slow worker-queue sample
was present in that window. Logging is thresholded and rate-limited, and older
lines have rotated: absence is not a percentile, utilization bound or proof of
no queueing. No message plaintext or credentials were exported.

The prior emulator's aggregate local stage sample included application gate wait
11,256 ms, mailbox service 8,352 ms and TLS-context readiness 6,134 ms. These are
client elapsed stages, not equivalent Pi service times. They support measuring
client CPU/scheduling and startup concurrency before blaming a server process.

| Approach | Likely benefit | Limits / required evidence |
| --- | --- | --- |
| Scoped off-gate waits | Removes demonstrated amplification of network waits into local Send | Credential ownership and lifecycle races require explicit fencing; initial password flow remains |
| Bounded asynchronous socket/RPC ownership | Avoids consuming one pool worker per idle/blocking socket | Requires measured admission/queue budgets, cancellation and shutdown tests; a larger worker minimum alone is not isolation |
| Control/bulk scheduling and healthy connection reuse | Protects mailbox/ACK admission from cache/history work and repeated TLS setup | Preserve per-device fairness, pinned authorization, bounded memory and request ordering; identify the actual queue before changing priority |
| Separate bulk-cache process | Can isolate bulk CPU, disk work and queues when OS resource limits are applied | Shared physical disk still contends; IPC and authority coordination add latency, memory, operational and failure modes |

No current evidence establishes that a process split is necessary to achieve the
target or would improve these client-side waits. Recommended next step is
correlated physical traces plus per-lane queue/TLS/native/durable-ACK measurements
under controlled load, then the smallest evidenced scheduling repair.

If a split becomes justified, the minimal design keeps account/device/revocation
authority and durable mailbox/ACK ownership in one control service. A bounded
bulk worker receives authenticated local IPC commands for ciphertext operations
only. Immutable operation IDs, exact audience/device/generation binding and
idempotent results are required. The authority owner must fence admission through
durable completion and drain/invalidate admitted work when revocation completes;
a stale short-lived token alone cannot preserve the existing revocation guarantee.
The worker cannot create delivery ACKs or interpret identity trust. Bounded queues,
per-account backpressure, crash-recovery ownership, commit ordering, and OS CPU/IO
limits need explicit tests. Rollback must preserve current durable messages,
revocations and partial-transfer journals rather than restore an older database.
This design is investigation only; a split, protocol/security change or major
rewrite requires new approval.
